# Deploy GeoAnnotator on Render.com + Neon.tech

Quick deployment guide using Render.com for services and Neon.tech for PostgreSQL database.

## Architecture

- **Database**: Neon.tech (serverless PostgreSQL + PostGIS)
- **Services** (Render.com):
  - Backend (Web Service - Django API)
  - Celery Worker (Background Worker - async emails)
  - Celery Beat (Background Worker - scheduled cleanup)
  - Redis (Managed Service - Celery broker)
- **Frontend**: Vercel

## Step 1: Create Neon Database

1. Go to [Neon Console](https://console.neon.tech/)
2. Click **"New Project"**
3. Configure:
   - **Name**: `geoannotator`
   - **Region**: Choose closest to Render services (e.g., `eu-central-1` for Europe)
   - **PostgreSQL**: Version 15 or 16
4. Click **"Create Project"**

5. **Enable PostGIS**:
   - In your project, go to **SQL Editor**
   - Run:
     ```sql
     CREATE EXTENSION IF NOT EXISTS postgis;
     ```

6. **Copy Connection String**:
   - Go to **Dashboard** → **Connection Details**
   - Copy the connection string (looks like):
     ```
     postgresql://user:password@ep-xxxxx.region.aws.neon.tech/neondb?sslmode=require
     ```
   - Save this - you'll need it as `DATABASE_URL`

## Step 2: Deploy to Render with Blueprint

### Quick Method (Recommended)

1. **Push code to Git**:
   ```bash
   git add render.yaml
   git commit -m "Add Render deployment config"
   git push origin main
   ```

2. **Create Blueprint on Render**:
   - Go to [Render Dashboard](https://dashboard.render.com/)
   - Click **"New +"** → **"Blueprint"**
   - Connect your GitHub/GitLab repository
   - Select branch (`main`)
   - Click **"Apply"**

Render will automatically create 4 services:
- ✅ geoannotator-backend (Web)
- ✅ geoannotator-celery-worker (Worker)
- ✅ geoannotator-celery-beat (Worker)
- ✅ geoannotator-redis (Redis)

## Step 3: Configure Environment Variables

After Blueprint deployment, configure these variables **for each service**:

### Backend Service

Navigate to: Dashboard → geoannotator-backend → Environment

**Add these variables**:

```bash
# Database (Neon)
DATABASE_URL=postgresql://user:password@ep-xxxxx.region.aws.neon.tech/neondb?sslmode=require

# Security Keys
FERNET_KEY=<generate-new-key>  # See "Generate Keys" section below
SECRET_KEY=<auto-generated-by-render>  # Leave as is

# Email Configuration
EMAIL_HOST_USER=geoannotator.noreply@gmail.com
EMAIL_HOST_PASSWORD=<gmail-app-password>  # See "Gmail App Password" section
DEFAULT_FROM_EMAIL=geoannotator.noreply@gmail.com

# Frontend
FRONTEND_URL=https://your-app.vercel.app
CORS_ALLOWED_ORIGINS=https://your-app.vercel.app

# Storage (Optional - configure if using S3/MinIO)
AWS_ACCESS_KEY_ID=<your-key>
AWS_SECRET_ACCESS_KEY=<your-secret>
AWS_STORAGE_BUCKET_NAME=geoannotator
AWS_S3_ENDPOINT_URL=<your-s3-endpoint>
```

### Celery Worker Service

Navigate to: Dashboard → geoannotator-celery-worker → Environment

**Add these variables** (same as Backend):

```bash
DATABASE_URL=<same-as-backend>
FERNET_KEY=<same-as-backend>
EMAIL_HOST_USER=<same-as-backend>
EMAIL_HOST_PASSWORD=<same-as-backend>
DEFAULT_FROM_EMAIL=<same-as-backend>
```

### Celery Beat Service

Navigate to: Dashboard → geoannotator-celery-beat → Environment

**Add these variables**:

```bash
DATABASE_URL=<same-as-backend>
FERNET_KEY=<same-as-backend>

# IMPORTANT: For database backups to work with Neon.tech
# Use the DIRECT connection URL (not pooled connection)
# Get this from Neon Console → Connection Details → "Direct connection"
BACKUP_DATABASE_URL=postgresql://user:password@ep-xxxxx.region.aws.neon.tech/neondb?sslmode=require&options=endpoint%3Dep-xxxxx

# S3 Configuration for backups (optional but recommended)
AWS_ACCESS_KEY_ID=<your-s3-access-key>
AWS_SECRET_ACCESS_KEY=<your-s3-secret-key>
AWS_STORAGE_BUCKET_NAME=geoannotator-backups
AWS_S3_ENDPOINT_URL=<your-s3-endpoint>  # Optional, for non-AWS S3
```

> **⚠️ Critical for Neon.tech**: The `DATABASE_URL` uses a **pooled connection** which doesn't work with `pg_dump`. You MUST set `BACKUP_DATABASE_URL` with the **direct connection URL** to avoid "Control plane request failed" errors. See [Database Backup Troubleshooting](./database-backup-troubleshooting.md) for details.
```

**Note**: Redis connection is automatically configured via `fromService` in `render.yaml`.

## Step 4: Run Migrations

1. Go to: Dashboard → geoannotator-backend
2. Click **"Shell"** tab
3. Run:
   ```bash
   python manage.py migrate
   ```

Expected output:
```
Running migrations:
  Applying contenttypes.0001_initial... OK
  Applying auth.0001_initial... OK
  ...
  Applying points.0001_initial... OK
```

## Step 5: Create Superuser

Still in the Backend Shell:

```bash
python manage.py createsuperuser
```

Enter:
- Email: `admin@example.com`
- Username: `admin`
- Password: (choose a strong password)

## Step 6: Verify Deployment

### Check All Services are Live

In Render Dashboard, ensure all 4 services show **"Live"** status:
- ✅ geoannotator-backend
- ✅ geoannotator-celery-worker
- ✅ geoannotator-celery-beat
- ✅ geoannotator-redis

### Check Logs

**Backend logs** should show:
```
[INFO] Starting gunicorn 21.2.0
[INFO] Listening at: http://0.0.0.0:10000
[INFO] Using worker: sync
[INFO] Booting worker with pid: X
```

**Celery Worker logs** should show:
```
[INFO/MainProcess] Connected to redis://...
[INFO/MainProcess] celery@... ready.
[INFO/MainProcess] Tasks:
  - apps.authentication.tasks.send_email_async
  - apps.authentication.tasks.cleanup_deleted_users
  - apps.authentication.tasks.cleanup_expired_confirmation_tokens
```

**Celery Beat logs** should show:
```
[INFO/Beat] Scheduler: Starting...
[INFO/Beat] DatabaseScheduler: Schedule changed.
```

### Test Email Sending

1. Visit your frontend
2. Register a new account
3. Check if confirmation email is received
4. Check Celery Worker logs for:
   ```
   [INFO/ForkPoolWorker-1] Task apps.authentication.tasks.send_email_async[...] succeeded
   ```

### Test Database Backups (Optional)

If you configured S3 storage for backups:

1. Go to Backend Shell on Render
2. Run manual backup test:
   ```bash
   python manage.py backup_database --dry-run --verbose
   ```

If you see errors like "Control plane request failed", check that:
- ✅ `BACKUP_DATABASE_URL` is set with the **direct connection** URL from Neon
- ✅ AWS S3 credentials are configured correctly

See [Database Backup Troubleshooting](./database-backup-troubleshooting.md) for details.

## Generate Keys

### FERNET_KEY (Encryption)

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Output example: `Xg3zP8KqR_NmJ9vY2wB5aT1cD0eF7hI6jL4kM3nO8pQ=`

**⚠️ Important**: Use the same `FERNET_KEY` for all services (Backend, Worker, Beat).

### SECRET_KEY (Django)

Render auto-generates this. You can also generate manually:

```bash
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

## Gmail App Password

To send emails via Gmail SMTP:

1. Go to [Google Account Security](https://myaccount.google.com/security)
2. Enable **2-Step Verification** (if not already enabled)
3. Search for "**App passwords**"
4. Select:
   - **App**: Mail
   - **Device**: Other (Custom name)
   - **Name**: GeoAnnotator Render
5. Click **"Generate"**
6. Copy the 16-character password (no spaces)
7. Use this as `EMAIL_HOST_PASSWORD`

**⚠️ Never commit this password to Git!**

## Troubleshooting

### Error: "Connection to Redis lost"

**Cause**: Redis service not started or wrong URL

**Solution**:
1. Check Redis service is "Live" in Render dashboard
2. Verify `CELERY_BROKER_URL` is auto-populated (via Blueprint)
3. Restart Celery workers

### Error: "Database connection failed"

**Cause**: Wrong Neon connection string or database not ready

**Solution**:
1. Verify `DATABASE_URL` is correct (copy from Neon dashboard)
2. Check Neon database is active (not paused)
3. Ensure connection string includes `?sslmode=require`

### Emails not sending

**Cause**: Invalid Gmail App Password or missing variables

**Solution**:
1. Verify `EMAIL_HOST_PASSWORD` is 16 characters (no spaces)
2. Check `EMAIL_HOST_USER` matches Gmail address
3. Verify 2-Step Verification is enabled on Gmail
4. Check Celery Worker logs for SMTP errors

### Services sleeping (cold starts)

**Cause**: Free tier auto-sleep after 15 minutes

**Solutions**:
- **Option A**: Upgrade to paid tier ($7/service)
- **Option B**: Use external ping service (UptimeRobot, cron-job.org)
- **Option C**: Accept 30-50s cold start delay

### Neon database connection limit

**Cause**: Free tier has connection limits

**Solution**:
1. Add connection pooling in Django settings:
   ```python
   DATABASES['default']['CONN_MAX_AGE'] = 60
   ```
2. Or upgrade to Neon Launch plan ($19/month)

### Automatic (Recommended)

Enable "Auto-Deploy" in Render dashboard:
- Dashboard → Service → Settings → Build & Deploy
- Toggle "Auto-Deploy" to **Yes**

Now every push to `main` will automatically rebuild:

```bash
git add .

```

In Render Dashboard:
1. Select service
2. Click **"Manual Deploy"** → **"Deploy latest commit"**

## Monitoring

### Uptime Monitoring (Free)

Use [UptimeRobot](https://uptimerobot.com/):
1. Create account
2. Add HTTP(s) monitor:
   - URL: `https://geoannotator-backend.onrender.com/api/v1/health/`
   - Interval: 5 minutes
3. Configure email alerts

### Error Tracking

Add [Sentry](https://sentry.io/) for production error tracking:

1. Create Sentry project
2. Add to `backend/requirements/production.txt`:
   ```
   sentry-sdk
   ```
3. Configure in `backend/config/settings/production.py`:
   ```python
   import sentry_sdk

   sentry_sdk.init(
       dsn="your-sentry-dsn",
       environment="production",
   )
   ```
4. Add `SENTRY_DSN` to Render environment variables

## Backup Database

### Neon Backups

Neon provides:
- **Point-in-time restore** (7 days for free tier, 30 days for Launch)
- **Manual backups**: Dashboard → Backups → Create backup

### Manual Backup

From your local machine:

```bash
# Install PostgreSQL client
brew install postgresql  # macOS
# or
sudo apt install postgresql-client  # Linux

# Backup (get connection string from Neon)
pg_dump "postgresql://user:password@ep-xxxxx.neon.tech/neondb?sslmode=require" > backup-$(date +%Y%m%d).sql

# Restore
psql "postgresql://user:password@ep-xxxxx.neon.tech/neondb?sslmode=require" < backup.sql
```
